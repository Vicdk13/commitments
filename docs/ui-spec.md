# Специфікація: покращення інтерфейсу «Домовленості з запису»

Версія 1 · 16.09.2026 · статус: чернетка на погодження
Проєкт `D:\Worker\commitments` — Next.js 16 + React, без UI-бібліотек; усі стилі в `src/app/globals.css`.

## 1. Мета і рамки

Людина за 30 секунд після завершення аналізу має:
(а) побачити відповідь «є домовленості чи ні», (б) перевірити будь-який пункт на слух в один клік,
(в) забрати результат туди, де працює (Slack, лист, нотатки).

Не змінюємо: пайплайн STT → LLM, схему відповіді моделі (крім UI-07 і UI-14), кольорові токени,
загальну структуру «доріжка + розмова | підсумок». Усе нижче — в межах поточної візуальної мови.

Пріоритети:
- **P0** — до здачі тестового (≈19.09): дешево, помітно, без ризику для eval. Разом ≈ 10 год.
- **P1** — якщо лишається час; торкається промпту/схеми або потребує калібрування. ≈ 7 год.
- **P2** — після здачі; продуктові кроки для беклогу.

## 3. Спільні зміни в даних (потрібні для P0)

**`src/lib/annotations.ts`** — розширити `Annotation`:

```ts
export type Flag = {
  kind: "no-owner" | "relative-deadline" | "low-confidence";
  label: string;          // «без власника», «дата не визначена», «впевненість низька»
  note?: string | null;   // пояснення моделі — у title чіпа
};

export type Annotation = {
  // …як зараз
  n: number;      // порядковий номер за часом цитати, з 1 (UI-04)
  flags: Flag[];  // попередження для чіпів (UI-10)
};
```

`buildAnnotations` після сортування проставляє `n = index + 1` і збирає `flags`:
- `no-owner` — `status === "accepted" && !owner`; `note = ownerNote`
- `relative-deadline` — `deadline.text && !deadline.resolvable`; `note = deadline.note`
- `low-confidence` — `confidence !== "high"`

`meta` лишається для тултіпа доріжки й картки в розшифровці, але **без** «без власника» — воно переїжджає у `flags`.

**`src/app/page.tsx`** — стан відтворення: `const [playing, setPlaying] = useState(false)`
з подій `play` / `pause` / `ended` на `<audio>` (той самий `useEffect`, що й курсор).
У `Summary`, `Transcript`, `Timeline` передається `playingId = playing ? activeId : null`.

## 4. Вимоги P0

### UI-01 Порядок блоків на вузьких екранах

**Проблема.** На ≤980px `.layout` стає однією колонкою в DOM-порядку: доріжка → усі 27 реплік → і лише потім «Підсумок». Головний результат — за трьома екранами скролу.

**Рішення (лише CSS, у `@media (max-width: 980px)`).** `.main, .side { display: contents }` — їхні діти стають елементами сітки `.layout` (одна колонка), далі `order`:

| Елемент | order |
|---|---|
| `.side-head` (заголовок «Підсумок» + кнопки) | 1 |
| `.sum`, `.side-wait` | 2 |
| `.tl` (доріжка, зокрема `.tl.skeleton`) | 3 |
| `.panel` (розмова) | 4 |
| `.metrics` | 5 |

```
[плеєр — липкий, UI-06]
[Підсумок: статус · Прийнято 3 · Скасовано 1 · …]
[Доріжка]
[Розмова]
[Час і вартість]
```

**Приймання.** На 375×812 після завершення статус-картка починається не нижче 900px від верху сторінки; порядок підсумок → доріжка → розмова → метрики; на ≥981px нічого не змінюється.

### UI-02 Компактна шапка після завершення

**Проблема.** До статус-картки ≈ 600px: заголовок з описом, панель моделі, файл-бар, два степи. Після завершення степи дублюють таблицю «Час і вартість»; панель моделі ставить перед новачком питання «яка модель?» раніше, ніж «що це робить».

**Рішення.**
1. `.has-result header.top p { display: none }` — після результату опис ховається, `h1` і meta лишаються.
2. Панель моделі → розкривний блок (`useState(open)`, не `<details>`, бо закривати треба з коду).
   Згорнуто — один рядок: `Аналіз: Claude Sonnet 5 · medium · ≈$0,02/хв  [Змінити]`.
   Розгорнуто — поточні селекти, примітка, кнопка «Проаналізувати цією моделлю» (як зараз, лише коли є розшифровка).
   За замовчуванням згорнуто — і до файлу, і після результату; після успішного запуску — згортається; під час обробки — заблоковано.
3. Степи: під час `transcribing` / `extracting` / `error` — як зараз. Коли `stage === "done"` — `.steps` не рендериться, а його зміст переїжджає у другий рядок файл-бару (`.dur`):
   `2:36 · 27 реплік · ukr · розпізнано за 9,1 с · Sonnet 5 за 27,7 с` (час — активного прогону).

```
Домовленості з запису                                  до 3 хв · 2 спікери · одна мова
┌──────────────────────────────────────────────────────────────────────────────────┐
│ Аналіз: Claude Sonnet 5 · medium · ≈$0,02/хв                          [Змінити]  │
├──────────────────────────────────────────────────────────────────────────────────┤
│ 02-variant.mp3   [▶ ─────────── 0:44 / 2:36 ─────────── 🔊]        [Інший файл]  │
│ 2:36 · 27 реплік · ukr · розпізнано за 9,1 с · Sonnet 5 за 27,7 с                │
└──────────────────────────────────────────────────────────────────────────────────┘
```

**Приймання.** На 1180px від верху сторінки до статус-картки ≤ 300px (зараз ≈ 600); під час обробки таймери й «зазвичай 10–25 с» видно, як раніше; повторний аналіз іншою моделлю — «Змінити» → вибір → «Проаналізувати».

### UI-03 Іконки статусів

**Проблема.** Чотири статуси відрізняються лише кольором; у чорно-білому режимі «прийнято» і «скасовано» однакові.

**Рішення.** Компонент `KindIcon({ kind, size = 12 })` — інлайн-SVG, `currentColor`, `aria-hidden`:
accepted — галочка, cancelled — хрестик, proposed — тире, question — знак питання.

Де: легенда доріжки (`.tl-k i` → іконка), картки в розшифровці (перед `.tr-ann-k`), заголовки груп у підсумку (`.sum-group h3`), тултіп маркера. На самих маркерах доріжки — номер (UI-04): номер веде до пункту, де іконка вже є.

**Приймання.** DevTools → Rendering → Emulate vision deficiencies → Achromatopsia: усі чотири види розрізняються в підсумку й розшифровці. Текстові підписи лишаються — іконка доповнює, не замінює.

### UI-04 Нумерація маркерів ↔ пунктів

**Проблема.** Зв'язок «маркер на доріжці → пункт у підсумку» видно лише на hover; на мобільному hover нема.

**Рішення.** `n` з `annotations.ts`.
- Маркер доріжки: коло 18px кольору виду, білий номер 10px `--mono` bold; активний — scale 1.25 + кільце (як зараз).
- Підсумок: `.sum-n` перед текстом — номер у кольорі виду, mono 11px.
- Картка в розшифровці: `.tr-ann-k` → «3 · ПРИЙНЯТО».
- Тултіп маркера: «#3 Прийнято · 0:44».
- Номери перераховуються для кожного прогону; в експорті (UI-11) — ті самі.

**Приймання.** Без наведення зрозуміло, який маркер якому пункту відповідає; при перемиканні прогону номери оновлюються.

### UI-05 Картка пункту: цитата, афорданс ▶, стан «грає»

**Проблема.** Картка — кнопка без візуального натяку, що її можна прослухати; таймкод — сірий текст; цитата, на якій тримається пункт, видна лише після кліку.

**Макет `.sum-item`:**

```
 3  Повернути темну тему (основні екрани),            ← .sum-n + .sum-t
    налаштування лишаються світлими
    [Дмитро] [⚠ до середи наступного тижня]           ← чіпи (UI-10)
    «…повернемо темну тему на основні екрани, а        ← .sum-q, max 2 рядки
    налаштування поки лишимо…»              [▶ 0:44]  ← .sum-play
    Тему спочатку прибрали (0:12), потім…             ← .sum-h, RichNote (UI-07)
```

- `.sum-q` — `quote.text` у лапках «…», курсив, `--ink-2`, `-webkit-line-clamp: 2`.
- `.sum-play` — чіп 24px, mono, рамка `--line`, `▶ 0:44`; hover — рамка `--accent`.
  `playingId === a.id` → `⏸ 0:44`, фон `#f2f7ff`, рамка accent. Активний на паузі → `▶`, картка `.active` як зараз.
  Чіп — `<span>`, не кнопка (кнопка в кнопці неприпустима); клік — по всій картці, як зараз.
- Картки в розшифровці `.tr-ann`: додати той самий чіп праворуч; цитата не потрібна — слова вже підсвічені.
- Підказка в `.side-head` під «Підсумок», дрібним: «клік по пункту — прослухати цитату».

**Приймання.** Без інструкції зрозуміло, що пункт можна прослухати; під час програвання одночасно видно, який пункт грає, — у підсумку, розшифровці й на доріжці; повторний клік — пауза.

### UI-06 Липкий плеєр

**Проблема.** `.side` sticky, а файл-бар із `<audio>` — ні: читаєш розшифровку — нема як поставити на паузу.

**Рішення.**
- `.has-result .filebar { position: sticky; top: 0; z-index: 20; box-shadow: 0 1px 0 var(--line) }`.
- `.side { top: 80px }` (висота файл-бару ≈ 62px + 16); якщо підсумок довший за вьюпорт — `.side { max-height: calc(100vh - 96px); overflow-y: auto }`.
- На ≤640px файл-бар — два рядки: `[назва з ellipsis · Інший файл]` / `[audio на всю ширину]`; висота ≤ 96px.

**Приймання.** При прокрутці розшифровки до кінця плеєр і «Інший файл» лишаються доступними; sticky-підсумок не ховається під файл-баром.

### UI-07 Посилання на час замість «turn N»

**Проблема.** У `history` модель пише «(turn 3)» — номер репліки з промпту протікає в UI.

**Рішення (два шари).**
1. Промпт (`extract.ts`, SYSTEM), додати правило: «У полях history, owner_note, deadline_note, status_reason не згадуй номери реплік. Якщо треба вказати місце в розмові — пиши час у форматі m:ss, як у розшифровці, напр. “(0:12)”.» Розшифровка в промпті вже містить час кожної репліки.
2. Клієнт: `RichNote({ text, turns, onSeek })`:
   - `\b(\d{1,2}):(\d{2})\b` → `<button class="t-ref">` (mono, accent, пунктирне підкреслення) → `onSeek(sec)`;
   - страхувальна заміна `\bturn[\s_-]?(\d+)\b` → `fmtTime(turns[n].start)` з тим самим посиланням, якщо `turns[n]` існує.
   Використовується для `history`, `ownerNote`, `statusReason`, `deadline.note`.

**Приймання.** `npx tsx scripts/eval.ts --cached` — 35/35 після зміни промпту; у трьох семплах у UI немає слова «turn»; клік по «(0:12)» перемотує плеєр.
**Ризик.** Зміна промпту може зачепити інші поля — порівняти `history` до/після очима на трьох семплах.

### UI-08 Скрол розшифровки без стрибка сторінки

**Проблема.** `scrollIntoView({ block: "center" })` центрує елемент у кожному прокручуваному предку — і в `.tr`, і у вікні: клік по пункту смикає всю сторінку.

**Рішення.** `ref` на контейнер `.tr` (`position: relative` у CSS); при зміні `active`:

```ts
const c = box.current, el = rows.current.get(active.quote.turnIndex);
if (!c || !el) return;
if (c.scrollHeight > c.clientHeight) {            // десктоп: лише контейнер
  c.scrollTo({ top: el.offsetTop - (c.clientHeight - el.offsetHeight) / 2, behavior: "smooth" });
} else {                                           // мобільний: контейнер не скролиться → вікно з поправкою на sticky
  const y = el.getBoundingClientRect().top + window.scrollY - STICKY_OFFSET - 16;
  window.scrollTo({ top: y, behavior: "smooth" });
}
```

**Приймання.** На десктопі клік по пункту не змінює `window.scrollY`; на мобільному репліка з'являється одразу під липким плеєром.

### UI-09 Контраст, фокус, reduced motion

- `--ink-3: #868c9b` → `#646a78` (≈ 5,4:1 на білому, ≈ 4,9:1 на `--bg`; зараз ≈ 3,4:1 — не проходить AA для 12–13px, а на ньому вся мета-інформація). Перевірити на око `.sum-m`, `.tr-time`, `.tl-tick em`, `.metrics .fine`.
- `--prop: #5a6070` на `--prop-bg` ≈ 5,7:1 — не чіпаємо.
- `button:focus-visible, .tl-track:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px }`.
- `@media (prefers-reduced-motion: reduce)`: вимкнути `rise`, `shimmer`, `pulse` (`.tl, .tr-ann, .sum-item, .sk-line, .sk-track, .step.running .dot { animation: none }`).

**Приймання.** axe DevTools — 0 помилок контрасту; Tab проходить семпли → селекти → пункти підсумку → таймкоди з видимим фокусом; при reduced motion нічого не анімується.

### UI-10 Попередження як чіпи

**Проблема.** «дата не визначена» — жовте, «без власника» — сірий текст у тому ж рядку, «впевненість середня» — курсив. Усі три однаково actionable.

**Рішення.** `.chip` (12px, radius 6, padding 1px 7px, фон `--bg`, рамка `--line`) і `.chip.warn` (`--warn-bg` / `--warn` / `--warn-line`, префікс ⚠). Рядок мети картки:
`[власник]` · `[дедлайн]` (warn, якщо `relative-deadline`; `title = flag.note`) · `[⚠ без власника]` (`title = ownerNote`) · `[⚠ впевненість низька]`. Таймкод переїжджає в `.sum-play` (UI-05). Джерело — `flags` з розділу 3.

**Приймання.** Усі три типи попереджень виглядають однаково; при наведенні видно пояснення моделі.

### UI-11 Експорт текстом, фідбек копіювання

- «JSON» після кліку 1,5 с показує «Скопійовано ✓» (disabled); при помилці clipboard — «Не вдалося» і fallback: `<textarea>` з текстом для ручного копіювання (мобільні браузери без Clipboard API).
- Нова кнопка «Текст» поруч. `lib/exportText.ts` → `toMarkdown(run, fileName, durationSec, transcribeMetrics?)` — чиста функція:


Порожні групи пропускаються; номери — ті самі `n`, що в UI; для `no_commitments` / `cannot_conclude` — лише заголовок і причина.

**Приймання.** Вставка у Slack / Notion / лист читається як список; «JSON» → «Скопійовано ✓».

### UI-12 Курсор і тултіп доріжки біля країв

**Рішення.** Клас на `.tl-cursor`: `edge-l` при `currentTime / dur < 0.04`, `edge-r` при `> 0.96`; CSS: `.tl-cursor.edge-r em { left: auto; right: 0; transform: none }`, `.edge-l em { left: 0; transform: none }`. Те саме для `.tl-tip` за `hover.quote.start / dur` з порогами 0.15 / 0.85 (тултіп ширший).

**Приймання.** Наприкінці запису мітка «2:36» повністю в межах панелі; тултіп першого й останнього маркера не обрізається.

## 5. Вимоги P1

### UI-13 Перемикач прогонів

Коли `runs.length > 1` — над статус-карткою сегментований контрол: `#1 Sonnet 5 · medium` | `#2 Opus 5 · high`; активний — фон `--ink`, білий текст; `title` з лічильниками «3 · 1 · 2 · 2». Клік = `setActiveRunId`. Рядки в «Час і вартість» лишаються клікабельними, але перестають бути єдиним (схованим у `title`) способом.

**Приймання.** Наявність двох прогонів видно одразу; перемикання — один клік.

### UI-14 Дата запису → календарні дедлайни

- UI: у розкривному блоці налаштувань (UI-02) поле «Дата запису» (`<input type="date">`, за замовчуванням сьогодні, можна очистити). У `POST /api/extract` — `recordedAt: "YYYY-MM-DD" | null`.
- Промпт: якщо дата є — у user-повідомленні «Дата запису: 2026-09-16 (середа).» і правило: «Відносні дати переводь у календарні від дати запису: `deadline_date = YYYY-MM-DD`, `deadline_resolvable = true`; у `deadline_note` коротко, як порахував (“середа наступного тижня від ср 16.09 → 23.09”). Без дати запису — як раніше, `resolvable = false`.»
- Схема: `deadline_date: z.string().nullable()`; `types.ts`: `deadline.date: string | null`; `finalize` в `extract.ts` мапить поле.
- UI: чіп дедлайну показує «до ср 23.09», `title` = оригінальна фраза + note; якщо `resolvable = false` — як зараз (warn).
- Eval: `scripts/eval.ts` викликає без `recordedAt` → очікування не змінюються; додатково — один ручний прогін 02 з датою.

**Приймання.** 02-variant з датою 16.09.2026: «до середи наступного тижня» → 23.09.2026; без дати — поведінка як зараз; `--cached` 35/35.

### UI-15 Клавіатура

Глобальний `keydown` у `page.tsx` (ігнорувати, якщо фокус в `input / select / textarea`, або натиснуто Ctrl/Meta):
- `Space` — play/pause, лише якщо `activeElement` — `body` або `.tl-track` (на кнопці Space натискає її саму);
- `←` / `→` — −5 / +5 с; `Shift+←` / `→` — ±15 с;
- `J` / `K` — попередній / наступний пункт відносно `currentTime` → `pick`;
- `Esc` — пауза + `setActiveId(null)`.

`.tl-track`: `tabIndex=0`, `role="slider"`, `aria-valuemin/max/now`, `aria-label="Позиція відтворення"`; `←/→` працюють із фокусом на ній. У `.tl-head` праворуч — «клавіші ?» з `title`-списком.

**Приймання.** Повний цикл «вибрати семпл → перейти між рішеннями → прослухати → пауза» без миші.

### UI-16 Кластеризація близьких маркерів

**Проблема.** На 360px маркери 18–22px, розташовані ближче 14px (0:27 і 0:32 у 3-хв файлі), накладаються.

**Рішення.** Ширина доріжки через `ResizeObserver`; групувати анотації, у яких різниця `quote.start` у пікселях < 20. Кластер — маркер `--ink` кольору з числом елементів; тултіп — список «#3 Прийнято · …», «#4 Питання · …»; клік — `onPick` першого, повторний — наступного по колу. Пункти лишаються доступними в підсумку.

**Приймання.** На 375px жоден маркер не перекриває інший; кожна анотація досяжна з доріжки.

### UI-17 Стартовий екран: семпли як картки

Три картки замість inline-кнопок: назва, тривалість, що демонструє (з README):
- «Планування релізу · 3:00 — усі 5 ситуацій: відхилена пропозиція, прийнята задача, змінений дедлайн, скасоване, задача без власника»;
- «Наступний день · 2:37 — одна домовленість змінена + сарказм, який не має стати зобов'язанням»;
- «Без домовленостей · 1:06 — обірваний запис, апка має відмовитись робити висновок».
На ≤640px — у стовпчик.

**Приймання.** Перевіряючий до кліку розуміє, який семпл що доводить.

## 6. Вимоги P2 (беклог)

### UI-18 Фільтр і пошук у розшифровці
Тумблер «лише репліки з рішеннями» (приховані згортаються в роздільник «··· 4 репліки ···», клік розгортає); поле пошуку з підсвіткою збігів і лічильником, `Enter` — наступний збіг.

### UI-19 Порівняння прогонів із відмінностями
`lib/diffRuns.ts`: зіставлення пунктів двох прогонів — спершу по `quote.turnIndex` + вид, далі по нормалізованому `task` (коефіцієнт Дайса ≥ 0,6). Бейджі в картці: «лише в цьому прогоні», «у #1: інший статус / власник / дедлайн». Над підсумком: «Відрізняється від #1: 2 пункти» → фільтр лише відмінностей. Прямий доказ для рішення «Sonnet замість Opus».

### UI-20 Людина в циклі
На кожній картці: ✓ підтвердити · ✗ помилка · ✎ виправити (task / owner / deadline inline). Стан — `localStorage` за ключем `hash(file) + run.id`; експорт (UI-11) включає позначки; «Зберегти як кейс» пише JSON у форматі `expected.json` для поповнення тестового набору. Користувач отримує чесний список, продукт — дані для оцінки якості.

### UI-21 Впевненість STT по словах
Scribe повертає `logprob` на слово (перевірити у відповіді API; `ScribeWord` зараз його не зберігає) → `Word.logprob`. У розшифровці слова нижче порога (калібрувати на семплах, орієнтир −0,5…−1) — пунктирне підкреслення; якщо таке слово є в цитаті пункту — чіп «⚠ нечітке слово в цитаті». Прямо покриває кейс «переписав / б переписав» із NOTES п. 4.

### UI-22 Кастомний плеєр і режим «слідкувати»
Замість нативного `<audio>`: play/pause, час, швидкість 1× / 1,25× / 1,5× / 2×, гучність; перемотка — лише через доріжку (один скрабер замість двох). Режим «слідкувати за розмовою»: авто-прокрутка розшифровки до репліки, що грає, якщо користувач не скролив останні 3 с (тумблер у `.panel-head`).
